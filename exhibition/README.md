# 展示版

体験者に、作業中を模した画面で「黒子の作業」をしてもらい、その途中に**本物のゆっくリフレッシュ**が差し込まれる展示版です。作業の中身に意味はありません。「作業中に差し込まれる」ことを体験してもらうためのものです。

展示版を起動すると、本物のゆっくリフレッシュ(`electron-main.js`)がトレイに常駐し、そのうえで展示の画面が開きます。体験者が「はじめる」を押すと、展示の画面がゆっくリフレッシュに「次の予定」を渡し、ゆっくリフレッシュ自身が予定5分前の判定で全画面で始めます。

## 展示用PCで使う(zip版)

展示版のzipを作ります。

```powershell
npm run make:exhibition
```

成果物は `out/exhibition/make/zip/win32/x64/ゆっくリフレッシュ展示版-win32-x64-<version>.zip` に出力されます。普段のアプリの成果物(`out/make`)とは混ざりません。

展示用PCでは、zipを展開して `ゆっくリフレッシュ展示版.exe` を起動します。Node.jsは要りません。

- 展示版の記録とGoogleのログインは `%APPDATA%\micro-slow-exhibition` に保存されます。普段のゆっくリフレッシュ(`%APPDATA%\micro-slow`)とは別なので、このPCで展示版を試しても普段の記録とは混ざりません
- 体験者が選んだ色は、展示版のゆっくリフレッシュのギャラリーに残ります
- 初めて起動したPCでは、最初の体験で自動的に「手入力のカレンダー」として初期設定が済みます。Googleカレンダーの予定も動かしたいときは、トレイのアイコンから「ゆっくリフレッシュを開く」でカレンダー連携をしてください。その場合は実際の予定の5分前にも差し込まれます
- zipにはGoogle OAuthのClient Secret(`config.local.js`)が入っています。展示用PC以外に配ったり、公開したりしないでください

## 開発中に動かす

```powershell
npm run exhibit
```

プロジェクト直下の `体験モードを起動.bat` をダブルクリックしても同じです。開発中はウィンドウ表示でも起動できます(全画面・ウィンドウの切り替えはしません)。

```powershell
npm run exhibit:windowed
```

起動時の引数:

- `--task=<id>`: 作業を固定し、開始画面を飛ばす(例: `--task=inbox`)

npm経由で渡す場合は `npm run exhibit -- --task=inbox` のようにします。

スタッフ用キー(展示の画面が前にあるとき):

- `Ctrl+Shift+R`: 開始画面へ戻る
- `Ctrl+Shift+S`: その場ですぐ差し込む
- `Ctrl+Shift+T`: 次の回に使う作業を切り替える(受信トレイ → タブとToDo → …)。画面の右下に作業名が一瞬出る。体験の途中で押すと次の回から変わり、起動し直しても覚えている
- `Ctrl+Shift+Q`: 終了(トレイのゆっくリフレッシュも一緒に終わる)
## 体験の流れ

1. 開始画面で「はじめる」を押す。どの作業になるかは、スタッフが `Ctrl+Shift+T` で選んでおく(体験者には選ばせない)
2. 作業する。作業中だけ全画面ではなく、タスクバーの上いっぱいのウィンドウになり、Windowsのタスクバー(と時計)が見える。作業ウィンドウの左下に「次の予定 HH:MM 定例ミーティング・あと◯分」が出て、ときどき通知も届く
3. 「はじめる」から `minLeadSeconds` 秒(既定20秒)以上あとの、いちばん近い分の区切りで(押してから20〜80秒後)、予定5分前として本物のゆっくリフレッシュが全画面で始まる。次の予定はその5分後に置かれる。作業は裏でも届き続ける
4. 色を選ぶとゆっくリフレッシュが消え、溜まった作業の画面に戻る
5. `reminderDelaySeconds` 秒後(既定3秒)に「まもなく HH:MM 定例ミーティング」が届く。「作業を閉じて向かう」か作業ウィンドウの×で、作業を閉じて予定へ向かう。応えなくても `autoLeaveSeconds` 秒後(既定30秒)には自動で閉じる
6. 「定例ミーティングへ」の画面を出し、`endCardSeconds` 秒後に開始画面へ戻る

ゆっくリフレッシュで作業の山が消えるわけではありません。山は残ったまま、整えた状態で次の予定へ向かう、という終わり方にしています。

展示の予定は、ゆっくリフレッシュの中では手入力の予定と同じように扱われます(`source: "exhibition"`)。展示用PCのカレンダーにほかの予定があっても必ず届き、Googleカレンダーを読み直しても消えません。次の回を始めるときや開始画面に戻るときに入れ替わり、アプリを起動し直すと消えます。

## ディレクトリ構成

```text
exhibition/
  app-main.js        展示版の入口。本物のゆっくリフレッシュを常駐させてから、展示の画面を開く
  main.js            展示の画面のウィンドウ(全画面・ウィンドウの切り替え、スタッフ用キー、ゆっくリフレッシュとのやりとり)
  preload.js         展示の画面に、上のやりとりの口を渡す
  config.js          差し込みのタイミング、予定名などの進行設定
  shell/             展示の画面(開始画面、作業ウィンドウ、通知、リマインド、終わりの画面)
  tasks/
    registry.js      作業の一覧(開始画面に出すものは config.js の taskIds で選ぶ)
    common/          作業で共通に使う部品(一時停止できるタイマー、文面、基本スタイル)
    inbox/           受信トレイ: 届くメールや依頼をボタンひとつで片づける
    tabs/            タブとToDo: ToDoを開くとその仕事のタブが開き、ページのボタンで片づける。開いたタブがたまって散らかる
    typing/          入力: 表示された言葉をローマ字で打ち込む(いまは config.js の taskIds に入れていない)
```

## 作業を増やすとき

1. `tasks/<id>/index.html` を作り、`../common/task-base.css` と `../common/task-kit.js` を読み込む
2. `tasks/registry.js` に1件足す(`id` はフォルダ名と同じにする)
3. `config.js` の `taskIds` に `id` を足す。挙げていない作業は、ファイルがあっても使われない

作業はシェルの作業ウィンドウの中にiframeで表示されます。ゆっくリフレッシュ中も作業は止まらず、裏で届き続けます。体験者が作業を閉じて予定へ向かうと、シェルから `pause` が届きます。`TaskKit.after` / `TaskKit.every` で作ったタイマーとCSSアニメーションは、そこで止まります。

作業を作るときの約束:

- スコア、残り時間、達成数、ゴールを出さない。中断されても失うものがないようにする
- 一つの操作は1〜2秒で終わるようにする。途中で止められても気にならない
- 中身は読まなくても進められる、ありがちな業務の文面にとどめる。実在の人物・会社・サービス名は使わない
- 「次々に来る」「溜まっていく」で忙しさを出す。正解・不正解は作らない
- Enterキーは使わない。ゆっくリフレッシュの終了キーと重なり、打っていた勢いで始まった直後に終えてしまうため
- 文字入力は物理キー(`event.code`)で受ける。会場のPCで日本語入力がオンでも打てるようにする
